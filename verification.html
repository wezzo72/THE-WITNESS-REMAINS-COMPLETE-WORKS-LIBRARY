Forensic Integrity

Each verified copy is byte-for-byte identical to the file retrieved from its source GitHub repository at the time of cloning, as confirmed by matching SHA-256 cryptographic hash.

A matching hash establishes that the stored file is an exact replica of the cloned object. It does not place the file on a blockchain, nor does it independently authenticate the content's authorship or truth-value beyond the GitHub provenance.

Users may independently verify any file by computing its SHA-256 and comparing it to the entry in the manifest. The repository commit history itself provides an additional chain of custody for this preservation copy.

Status categories in the search interface: verified (hash-matched copy), not-copied (identified but not included in this pass), lfs (pointer only).

Intellectual Framing

This is a finding aid and preservation archive of works attributed in the source repositories. Verification confirms file integrity and retrieval provenance from those repositories; it does not constitute independent scholarly adjudication of the factual, historical, or theological claims contained in the works.

The probability of exact match for any verified file is effectively certain given the collision resistance of SHA-256 under normal conditions. Completeness of the overall collection is bounded by the 17 enumerated repositories and the identification process described; works existing outside these repositories are outside the scope of this library.

The archive presents the works as they were found. Interpretations, prophetic significance, or other content claims remain those of the original authors and are not endorsed or verified by this preservation layer.

Legal Fortification
